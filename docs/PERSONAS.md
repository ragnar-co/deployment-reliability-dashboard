# PERSONAS — Deployment Reliability Dashboard

> เอกสารนี้เป็นเจ้าของ (canonical owner) ของ persona และ CP-ID ทั้งหมด เอกสารอื่นอ้างถึง CP-ID โดยไม่สร้างขึ้นใหม่

## Persona Profiles

| Field | P1 — DevOps Operator | P2 — Engineering Lead |
|---|---|---|
| name | DevOps Operator | Engineering Lead |
| role | ผู้นำเข้าประวัติ deployment และเริ่มสืบสวนเมื่อ deployment ล้มเหลว | ผู้ตัดสินใจว่าบริการใดควรได้รับความสนใจก่อน |
| technical_skill | สูง — คุ้นเคย CI/CD, log, container | ปานกลางถึงสูง — อ่านตัวเลขและแนวโน้มได้ แต่ไม่ลงรายละเอียด log |
| ความถี่ใช้งาน | ทุกครั้งที่มี deployment ล้มเหลว และเมื่อมีไฟล์ export ใหม่ | ทบทวนความน่าเชื่อถือเป็นรอบ |

## Pain Points

**P1 — DevOps Operator**
- ประวัติ deployment กระจายหลายที่ ต้องเปิดดูทีละแห่งเพื่อหาว่าบริการใดควรตรวจก่อน
- ไม่เห็นภาพรวมว่าบริการใดล้มเหลวบ่อยที่สุด จึงเสียเวลาเลือกจุดเริ่มต้นด้วยความรู้สึก
- ข้อความ error ต้องไล่หาเอง ไม่มีรายการรวมที่กรองตามบริการได้

**P2 — Engineering Lead**
- เปรียบเทียบความน่าเชื่อถือระหว่างบริการไม่ได้ในที่เดียว
- ไม่มีตัวเลขที่ยืนยันได้ว่าบริการใดต้องเร่งแก้ก่อน

## Primary Use Cases

| ID | Persona | Use case |
|---|---|---|
| UC-01 | P1 | นำเข้าไฟล์ CSV ประวัติ deployment แล้วเห็นว่าข้อมูลถูกบันทึกครบหรือถูกปฏิเสธเพราะอะไร |
| UC-02 | P1, P2 | ดูจำนวน deployment, อัตราสำเร็จ และเวลาเฉลี่ยของ deployment ที่สำเร็จ แยกตามบริการ |
| UC-03 | P1 | เลือกดูเฉพาะบริการเดียว เพื่อเห็นเฉพาะตัวเลขและรายการที่ล้มเหลวของบริการนั้น |
| UC-04 | P1 | อ่านรายการ deployment ที่ล้มเหลวพร้อมข้อความ error ต้นฉบับ เพื่อเริ่มสืบสวน |
| UC-05 | P2 | จัดอันดับบริการจากอัตราสำเร็จต่ำสุด เพื่อชี้ว่าควรเริ่มที่บริการใด |

## Critical Paths

ตารางนี้คือที่เดียวที่กำหนด CP-ID `Delivery = UI` ต้องปรากฏใน UI_SPEC.md (Critical Path Trace) และทุก CP-ID ต้องมี E2E scenario ใน TESTING.md อย่างน้อยหนึ่งรายการ

| CP-ID | Persona | Critical path (สิ่งที่พลาดไม่ได้) | Delivery |
|---|---|---|---|
| CP-01 | P1 | นำเข้า CSV ที่ถูกต้องแล้วเห็นข้อมูลของทุกบริการบนแดชบอร์ด | UI |
| CP-02 | P1 | เลือกบริการแล้วเห็นเฉพาะตัวเลขและ deployment ที่ล้มเหลวของบริการนั้นพร้อมข้อความ error | UI |
| CP-03 | P2 | เห็นลำดับบริการจากอัตราสำเร็จต่ำสุดเพื่อระบุจุดเริ่มตรวจสอบ | UI |
| CP-04 | P1 | CSV ที่ผิดกติกา (ไฟล์เกิน 10 MB, คอลัมน์ขาด, status/วันที่/ระยะเวลาไม่ถูกต้อง, `deployment_id` ซ้ำภายในไฟล์) ถูกปฏิเสธพร้อมเหตุผลระบุแถว และไม่มีข้อมูลบางส่วนถูกบันทึก | UI |
| CP-05 | P1 | อัปโหลดไฟล์เดิมซ้ำ (checksum เดียวกัน) หรือไฟล์ใหม่ที่มี `deployment_id` ซึ่งมีอยู่ในฐานข้อมูลแล้ว ต้องถูกตรวจพบและไม่สร้างข้อมูลซ้ำ | system |
| CP-06 | P1 | แอปที่ deploy บน Coolify ยังมีข้อมูลอยู่หลัง restart/redeploy (persistent volume) | system |
