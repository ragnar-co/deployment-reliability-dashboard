# VPD — Value Proposition Design

## Customer Profile
อ้างถึง persona P1 (DevOps Operator) และ P2 (Engineering Lead) ใน PERSONAS.md ไม่นิยามซ้ำ

## Customer Jobs
| ID | Persona | Job |
|---|---|---|
| CJ-01 | P1 | หาว่าบริการใดควรตรวจสอบก่อนเมื่อ deployment ล้มเหลว (UC-03, UC-05) |
| CJ-02 | P1 | อ่านข้อความ error ของ deployment ที่ล้มเหลวเพื่อเริ่มสืบสวน (UC-04) |
| CJ-03 | P1 | รวมประวัติ deployment จากไฟล์ export เข้าที่เดียว (UC-01) |
| CJ-04 | P2 | เปรียบเทียบความน่าเชื่อถือของบริการต่างๆ (UC-02) |

## Pains
| ID | Pain |
|---|---|
| PN-01 | ต้องเปิดดูประวัติหลายแห่งเพื่อเลือกจุดเริ่มต้น |
| PN-02 | ไม่มีตัวเลขเปรียบเทียบอัตราสำเร็จระหว่างบริการ |
| PN-03 | ไล่หาข้อความ error ของบริการหนึ่งๆ ได้ยาก |
| PN-04 | ไม่แน่ใจว่าไฟล์ที่นำเข้าถูกต้องครบถ้วนหรือซ้ำกับของเดิม |

## Gains
| ID | Gain |
|---|---|
| GN-01 | เห็นบริการที่อัตราสำเร็จต่ำที่สุดก่อน |
| GN-02 | ตัดสินใจได้เร็วจากตัวเลขเดียวกันที่ทุกคนเห็น |
| GN-03 | มั่นใจว่าข้อมูลบนจอตรงกับไฟล์ที่นำเข้า |

## Value Map
ผลิตภัณฑ์: เว็บแอปภายในที่นำเข้า CSV, เก็บใน SQLite และแสดงตัวชี้วัดความน่าเชื่อถือแยกตามบริการ

## Pain Relievers
| ID | Relieves | Reliever |
|---|---|---|
| PR-01 | PN-01 | หน้าเดียวรวมทุกบริการ |
| PR-02 | PN-02 | ตารางจำนวน deployment, success rate, เวลาเฉลี่ยของ success แยกบริการ |
| PR-03 | PN-03 | รายการ failed deployment พร้อม error ต้นฉบับ และตัวกรองตามบริการ |
| PR-04 | PN-04 | Validation ทั้งไฟล์ก่อนบันทึก, atomic import, checksum ตรวจไฟล์ซ้ำ |

## Gain Creators
| ID | Creates | Creator |
|---|---|---|
| GC-01 | GN-01 | เรียงบริการจาก success rate ต่ำสุด |
| GC-02 | GN-02 | ตัวเลขทั้งหมดอ่านจาก SQLite ที่เดียว |
| GC-03 | GN-03 | แสดงผลนำเข้า (จำนวนแถว/เหตุผลที่ถูกปฏิเสธ) ชัดเจน |

## Value Propositions
| ID | Proposition | Traces to |
|---|---|---|
| VP-01 | "เห็นว่าควรเริ่มตรวจบริการไหนก่อน ภายในหน้าเดียว" | PR-01, PR-02, GC-01 |
| VP-02 | "ลงถึง deployment และข้อความ error ที่ล้มเหลวของบริการที่เลือก" | PR-03 |
| VP-03 | "ข้อมูลที่เห็นเชื่อถือได้ เพราะนำเข้าแบบ atomic และตรวจซ้ำได้" | PR-04, GC-02, GC-03 |
