# PRD — Deployment Reliability Dashboard

## Problem Statement
ทีมพัฒนา deploy หลายบริการเป็นประจำ เมื่อ deployment ล้มเหลว ทีม DevOps ต้องเปิดดูประวัติหลายแห่งเพื่อหาว่าบริการใดควรตรวจสอบก่อน (PN-01…PN-04 ใน VPD.md) แอปนี้นำเข้าประวัติ deployment จาก CSV เก็บลง SQLite และแสดงตัวชี้วัดความน่าเชื่อถือแยกบริการพร้อมรายการที่ล้มเหลว เพื่อชี้จุดเริ่มตรวจสอบ

## Goals and Success Metrics
| ID | Goal | Metric | Target |
|---|---|---|---|
| G-01 | นำเข้าไฟล์ตัวอย่างได้ถูกต้อง | ตัวเลขรวมตรงกับค่าอ้างอิงของไฟล์ตัวอย่าง (36,527 แถว; success 33,643; failed 2,884; success rate 92.10%; เวลาเฉลี่ย success 187.8 วินาที) | ตรงทุกค่า |
| G-02 | ข้อมูลผิดกติกาไม่ถูกบันทึก | จำนวนแถวหลังถูกปฏิเสธ | ไม่เปลี่ยน (0 แถวบางส่วน) |
| G-03 | ส่งมอบตามกรอบเวลา | เวลารวมถึง deploy ที่เปิดใช้งานได้ | ≤ 120 นาที |
| G-04 | ผู้ใช้เลือกจุดเริ่มตรวจสอบได้จากหน้าเดียว | บริการ success rate ต่ำสุดอยู่บนสุดของตาราง | ผ่านการตรวจใน TESTING |

ค่าอ้างอิงในข้อ G-01 เป็นข้อเท็จจริงของไฟล์ตัวอย่างนี้ (คำนวณซ้ำจาก `theBeth_deployments_mock.csv` เมื่อ 2026-10-02: 36,527 แถว, 24 บริการ, `deployment_id` ไม่ซ้ำ, `release-validator` 79.29% ล้มเหลว 316) ไม่ใช่การรับประกันสำหรับไฟล์อื่น

## Functional Requirements
นิยามตัวชี้วัด (เจ้าของ):
- **Deployment count** = จำนวน record ทั้งหมดใน filter ที่เลือก
- **Success rate** = successful ÷ deployment ทั้งหมด × 100 (ปัด 2 ตำแหน่ง)
- **Average successful duration** = ค่าเฉลี่ยของ `duration_seconds` เฉพาะ `status = success` (หน่วยวินาที ไม่รวม failed)

## Acceptance Criteria
| ID | Criterion |
|---|---|
| AC-01 | ไฟล์ตัวอย่างถูกนำเข้าสำเร็จและแสดงจำนวน 36,527 แถว |
| AC-02 | ไฟล์ที่คอลัมน์ขาด, status ไม่ถูกต้อง, วันที่ไม่ถูกต้อง, duration ไม่เป็นจำนวนเต็มบวก, `deployment_id` ซ้ำภายในไฟล์, คอลัมน์เกิน, error_message ไม่สอดคล้องกับ status ถูกปฏิเสธพร้อมเหตุผล และจำนวนแถวในฐานข้อมูลไม่เปลี่ยน |
| AC-03 | อัปโหลดไฟล์เดิมซ้ำถูกปฏิเสธ; ไฟล์ใหม่ที่มี `deployment_id` ซ้ำของเดิมถูกปฏิเสธทั้งไฟล์ |
| AC-04 | ภาพรวมของไฟล์ตัวอย่างตรง G-01 |
| AC-05 | ตารางแยกบริการตรงกับการคำนวณอิสระจากไฟล์ตัวอย่างทุกบริการ (24 บริการ); บริการแรกคือ `release-validator` (79.29%, ล้มเหลว 316) |
| AC-06 | เมื่อเลือกบริการ ตัวเลขรวมและรายการเหลือเฉพาะบริการนั้น และทุกบริการให้ผลถูกต้อง |
| AC-07 | แถวล้มเหลวแสดง error_message ตรงกับต้นฉบับ |
| AC-08 | ไม่มีโค้ดอ่าน CSV เพื่อคำนวณตัวเลขหลังขั้นตอนนำเข้า (ตรวจโดย review/test) |
| AC-09 | `GET /health` ตอบ 200 เมื่อฐานข้อมูลเข้าถึงได้ |
| AC-10 | (P1) เมื่อเลือก environment ตัวเลขและรายการเปลี่ยนตาม |
| AC-11 | `python -m pytest -q` ผ่านโดยไม่ต้องมีไฟล์ตัวอย่างจริง; กรณีที่ไฟล์ตัวอย่างมีอยู่ ผลต้องตรง G-01 |
